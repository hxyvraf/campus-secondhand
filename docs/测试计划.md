# 校园二手交易平台 功能测试计划

## 一、测试目的

对校园二手交易平台（Web 端）v1.0.0 进行**功能测试**，验证 5 个业务模块（注册登录、商品发布与管理、搜索收藏、订单管理、消息通知）与管理端功能是否符合需求与接口文档约定，重点确认：

1. 主业务流程可完整走通（注册 → 登录 → 发布 → 搜索 → 收藏 → 下单 → 卖家确认 → 买家完成 → 消息可见）；
2. 异常与边界输入被正确拦截，并且返回的 HTTP 状态码、业务返回码、提示信息三者一致；
3. 订单状态机与商品状态联动正确，重复提交、越权操作、超时订单等风险场景得到控制；
4. 缺陷（若有）被完整记录、修复并回归。

### 2.3 不在范围

- 性能测试（并发下单、列表查询响应时间、定时任务在多实例下的幂等性）；
- 安全专项（SQL 注入、XSS、越权组合矩阵、令牌吊销策略、密码强度策略）；
- 兼容性专项（Chrome/Edge/Firefox、移动端浏览器、不同分辨率矩阵）；
- 非功能需求（可用性、可维护性、日志审计、备份恢复）；
- 支付、短信/邮件通知、图片云存储等未实现的能力。

## 六、准入与准出标准

### 6.1 测试准入（开始测试的条件）

1. 后端可编译启动（`mvn package` 成功），前端可正常构建启动；
2. 数据库可自动建库建表并写入初始数据，测试账号可用；
3. 接口文档（Swagger + Markdown）已提供，40 个接口路径与参数可查；
4. 主流程可手工走通，无阻塞性错误。

### 6.2 测试准出（结束测试的条件）

1. P0/P1 用例执行率 100%，通过率 ≥ 95%；
2. 全部严重及以上缺陷已修复并回归通过，遗留缺陷有明确结论与规避方案；
3. 接口自动化集合整体执行通过（断言全部通过），报告归档；
4. 测试用例、缺陷记录、测试报告三份文档已完成并通过自检。

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 定时任务超时关闭依赖真实等待（默认 30 分钟） | 超时场景用例执行周期长 | 提供管理端「手动触发超时扫描」接口 + SQL 造数把 `expire_at` 改成过去时间，用例可在秒级完成 |
| 接口之间存在数据依赖（登录 token、商品 ID、订单 ID） | 用例无法独立执行 | Postman 集合用环境变量串联，且必须按文件夹顺序整体运行；文档中明确执行顺序 |
| 测试数据被反复执行污染 | 断言数量、列表长度失真 | 提供「重置数据.bat」一键把数据库恢复到初始状态；用例断言尽量使用相对判断（如 ≥1、包含） |
| 前端用例人工执行易漏项 | 覆盖不完整 | 用例表按模块给出前置条件与步骤，执行状态列必须回填 |
| 时间不足导致范围蔓延 | 关键模块测不深 | 优先级排序：P0 主流程 → P1 异常/权限/状态 → P2 边界与易用性，P2 可延后 |
