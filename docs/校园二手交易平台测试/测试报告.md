### 6.2 重点缺陷

| 缺陷 ID | 严重程度 | 标题 | 影响 |
| --- | --- | --- | --- |
| B_01 | 极高 | 修改密码功能缺失 | 需求 REQ-AUTH-07 未实现 |
| DEF-001 | 严重 | 删除已上传的第 1 张图片后再上传第 2 张，发布后两张图片都被上传，被删图片成为主图 | 商品图片错误，影响交易信息可信度 |
| cat_B_01 | 高 | 分类展示模块多出需求未定义的筛选控件，拖动价格滑块弹出后端参数异常，整个分类模块崩溃 | 首页核心入口不可用 |
| login_B_04 ~ 06 | 高 | 用户名大小写校验缺失（全大写 / 全小写 / 大小写错位均可登录成功） | 账号校验不严 |
| pp_B_01 ~ 03 | 高 | 昵称 / 手机号 / 邮箱唯一性校验缺失，可改成其他账号已用的值 | 用户标识冲突 |
| reg_B_01 ~ 03 | 高 | 注册时昵称 / 手机号 / 邮箱已被占用仍可注册成功 | 唯一性约束缺失 |
| login_B_01 ~ 22 | 中 | 用户名或密码错误、长度越界、特殊字符与注入语句等 19 种异常输入，登录按钮一直加载且无任何错误提示 | 用户无反馈，体验差且无法定位问题 |
| search_B_01 ~ 03 | 中 / 轻微 | 关键词中间空格未处理、`%` `_` 未转义被当通配符、特殊字符处理规则不一致 | 搜索结果异常 |
| order_B_01 / pdd_B_01 | 中 / 轻微 | 卖家看不到买家下单时填写的留言（同一问题在两个模块各记录一次，建议合并） | 交易沟通信息丢失 |
| pp_B_04 ~ 12 | 中 / 低 | 校验失败时提示「参数校验失败」不说明具体原因；昵称超长被静默截断并提示保存成功 | 提示不明确，用户误以为成功 |

## 七、遗留问题与风险

| # | 遗留问题 | 影响 | 建议 |

| 1 | 46 条缺陷全部处于「未提交 / 未上报 / 新建」 | 没有修复与回归记录，无法判定版本质量 | 按优先级提交到缺陷管理工具，修复后回归并更新「修复说明 / 回归结果」列 |
| 2 | 登录模块 26 条用例未回填实际结果 | 执行率与结论缺少依据 | 按用例步骤回填实际结果，或明确标记为「未执行」 |
| 3 | 管理端、消息通知两个模块只有测试点梳理 | 覆盖不完整 | 补齐用例表并执行 |
| 4 | 商品发布与管理模块有 1 条用例明确标注「未执行」 | 该测试点结论缺失 | 补执行后回填 |
| 5 | 缺陷表字段填写不一致（如 pdd_B_01 的「严重程度」列填了 P3；《缺陷记录表示例》实为模板） | 统计口径不统一 | 统一枚举值：严重程度只填 极高/严重/高/中/低/轻微 |

| 7 | 历史数据累积会干扰数量类校验（列表条数、收藏数） | 结果失真 | 每轮执行前先「重置数据.bat」，并用相对判断 |

## 八、结论与建议

1. **设计侧**：测试点、用例、业务流程三类产出齐全，覆盖 11 个模块与 7 条业务流程，需求到用例的映射清楚，具备继续迭代的基础。
2. **执行侧**：266 条用例中 239 条已执行并回填（89.8%），但缺陷全部未进入修复闭环，**未达到《测试计划.md》第十节的准出标准**（P0 用例执行率与通过率 100%、严重与中等缺陷修复率 100% 且回归通过、已执行用例全部回填等）。
3. **质量侧**：本轮共发现 46 条缺陷，其中极高 1 条、严重 1 条、高 10 条，集中在**登录校验、唯一性校验、分类模块稳定性、商品图片上传**四处，建议优先修复这四类问题后再执行回归。
4. **下一步**：缺陷提交并修复 → 回归对应用例与 BP-01 主流程 → 回填用例实际结果 → 更新本报告的执行与缺陷统计。

## 附录 A：统计口径

- **叶子测试点**：XMind 中没有任何子节点的节点视为一个测试点；分组节点与根节点不计入。
- **用例数**：以用例表中「用例编号」列非空且非表头的行计数；模板文件（功能测试用例编写模板.xlsx）不计入。
- **执行分类**：
  - 与预期一致 → 实际结果文本含「一致」「符合预期」；
  - 不符合预期 → 实际结果文本含「与预期不符」「与预期不一致」「不符合预期」「已记缺陷」；
  - 现象记录 → 有实际结果文本、但未使用上述判定词（多为现象描述，其中已登记的异常见各模块缺陷记录表）；
  - 未执行/未回填 → 实际结果为空，或文本含「未执行」。
- **缺陷数**：以缺陷记录表中「缺陷ID」列非空且非表头的行计数；《缺陷记录表示例》《缺陷记录表模板》按模板处理不计入；《重要缺陷记录表》中的真实缺陷（B_01）计入。
- 本报告不按用例文本自动推断「通过率」——源用例表没有独立的执行结论列，通过 / 不通过以缺陷记录表登记的缺陷为准。
