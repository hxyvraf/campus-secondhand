# 校园二手交易平台 数据库设计

## 一、基本信息

| 项目 | 内容 |
| --- | --- |
| 数据库 | MySQL 8.0（`campus_trade`） |
| 字符集 | `utf8mb4` / `utf8mb4_general_ci` |
| 存储引擎 | InnoDB |
| 建库方式 | 后端启动时通过连接串参数 `createDatabaseIfNotExist=true` 自动建库，随后执行 `schema.sql` 建表、`data.sql` 写入初始数据 |
| 建表脚本 | `backend/src/main/resources/db/schema.sql` |
| 初始数据 | `backend/src/main/resources/db/data.sql`（INSERT IGNORE + 固定主键，可重复执行） |

## 二、表关系

```
        ┌──────────┐        ┌───────────┐
        │  user    │1      *│  product  │*      1┌──────────┐
        │ 用户表    ├────────┤  商品表    ├────────┤ category │
        └────┬─────┘ 发布    └─────┬─────┘  分类   └──────────┘
             │1                   │1
             │                    │*
             │              ┌─────┴───────┐
             │              │product_image│
             │              │ 商品图片表   │
             │              └─────────────┘
             │
     ┌───────┴────────┐        ┌──────────────┐
     │                │        │              │
     │*               │*       │*             │*
┌────┴─────┐    ┌─────┴─────┐  │        ┌─────┴──────┐
│ favorite │    │trade_order│  │        │  message   │
│ 收藏表    │    │  订单表    │  │        │ 站内消息表  │
└──────────┘    └───────────┘  │        └────────────┘
   （user + product 联合唯一）   └── user 作为买家/卖家/接收人
```

- `favorite`：用户 × 商品 多对多（`user_id + product_id` 唯一）
- `trade_order`：同时关联买家 `buyer_id` 与卖家 `seller_id`
- `message`：接收人 `user_id`，通过 `related_id` 关联订单或商品

## 四、关键设计说明

1. **金额使用 DECIMAL(10,2)**：避免浮点误差，最大 99,999,999.99，业务限制在 999,999.99 以内。
2. **商品逻辑删除**：`deleted` 字段配合 MyBatis-Plus 的 `@TableLogic`，删除后所有查询自动过滤，历史订单仍能关联到商品记录。
3. **收藏数冗余**：`product.favorite_count` 用于列表展示与「收藏最多」排序，收藏/取消收藏时同步更新，测试用例包含一致性校验 SQL。
4. **订单超时靠 expire_at**：下单时写入 `created_at + app.order.timeout-minutes`，定时任务每分钟扫描 `status='PENDING_CONFIRM' AND expire_at < now()`。
5. **重复下单防护**：业务层先查「同一买家 + 同一商品 + 进行中状态」的订单，再对商品做 `status='ON_SALE'` 的乐观更新（`UPDATE ... WHERE status='ON_SALE'`），保证并发下只有一个人能锁定商品。
6. **无外键约束**：为便于造数与重置数据，表之间不加物理外键，一致性由业务层与应用校验保证（典型互联网项目做法）。

## 六、常用校验 SQL

```sql
-- 订单状态与商品状态是否联动正确
SELECT o.id, o.status AS order_status, p.status AS product_status
FROM trade_order o JOIN product p ON p.id = o.product_id ORDER BY o.id DESC;

-- 收藏数与收藏表是否一致（应无结果）
SELECT p.id, p.favorite_count, (SELECT COUNT(*) FROM favorite f WHERE f.product_id = p.id) AS real_count
FROM product p WHERE p.favorite_count <> (SELECT COUNT(*) FROM favorite f WHERE f.product_id = p.id);

-- 每个用户的未读消息数
SELECT user_id, COUNT(*) AS unread FROM message WHERE is_read = 0 GROUP BY user_id;

-- 超时订单与商品状态
SELECT o.id, o.status, o.expire_at, p.status AS product_status
FROM trade_order o JOIN product p ON p.id = o.product_id
WHERE o.status IN ('PENDING_CONFIRM', 'TIMEOUT');
```
